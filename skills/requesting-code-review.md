# Requesting Code Review

## Philosophy
Before submitting tasks or branches, run a comprehensive pre-review checklist. Review against the plan and report issues by severity.

## Methodology
1. **Pre-Review Checklist**: Review all changed files. Check for coding standards, security, edge cases, and performance issues.
2. **Review Against Plan**: Verify that all tasks from the plan have been completed and meet the original requirements.
3. **Report Issues**: Detail any issues found with severity ratings (Critical, High, Medium, Low).
4. **Block Progress**: Critical and high issues must be fixed before proceeding to QA or merging.
5. **Verify Fixes**: Ensure that fixes adequately address the reported issues and tests pass.

## When to use
Activates between tasks and before handing off to QA or the final human review.
